## 2. Variable collections (mirror the token tiers)

**Do this with the plugin, not by hand.** `tools/figma-plugin/` creates both collections, all six
modes, 271 variables and 696 alias assignments in one run — the tokens are baked into the plugin by
`npm run build`, so running it is: open the plugin, press **Import**. See `tools/figma-plugin/README.md`.
Re-running it after a build is also how a later token change reaches Figma.

Entering 271 variables by hand takes hours and gets an alias wrong somewhere; the plugin's report
tells you if any alias failed to resolve. The manual steps below are the specification of what
*should* exist — use them to review the result, or as the fallback if the plugin cannot run.

Six tokens the plugin cannot import, because Figma has no variable type for a curve: `curve/standard`,
`curve/emphasized`, `curve/out`, `curve/in-out`, `easing/standard`, `easing/emphasized`. Set easing by
hand on prototype interactions. The plugin lists exactly these six as skipped.

Open *Local variables* (right panel → Variables).

**Collection `Primitives`** — no modes. **159 variables.** Everything under `Primitives` in `dist/figma/tokens.json`, named exactly like the token paths with `/` instead of `.`.

Colour ramps: the base set (`color/neutral/*`, `color/blue/*`, `color/red/*`, `color/green/*`, `color/amber/*`, `color/white`, `color/black`) **plus the linen palette** (`color/linen/*`, `color/ink/*`, `color/ultramarine/*`, `color/crimson/*`, `color/jade/*`, `color/ochre/*`, `color/oxblood/*`). Values: the `$value.hex` field.
Numbers: `space/0` … `space/16`, `size/6` … `size/12`, `radius-scale/1` = 4, `radius-scale/1-5` = 6, `radius-scale/2` = 8, `radius-scale/3` = 12, `radius-scale/3-5` = 14, `radius-scale/full` = 9999, `border-width/1` … `/3`, `duration/0` … `duration/700`, `line-height/*`, `font/size/*`, `font/weight/*`, `tracking/*`.
Figma numbers are unitless: `px` is assumed, `font/size/*` is `rem` in CSS and must be entered as px (× 16), and `tracking/*` is in `em` — enter it as a percentage on the text style, not as a variable, since Figma has no em-valued number.
Set the collection to *hidden from publishing* (collection settings → Hide from publishing) so designers can only pick semantic variables.

**Collection `Semantic`** — modes, in this order: `light` (default), `dark`, `hc-light`, `hc-dark`, `linen`, `linen-dark`. Mode names match `attribute` in `tokens/themes.config.ts`, so a mode maps 1:1 to `data-iz-theme`. **118 variables** — everything under `Semantic` in `dist/figma/tokens.json`.

**Every value is an alias**: click the value → the variable icon → pick the primitive. Per mode, use `Semantic.<name>.$extensions["design.iz.figma"].modes.<mode>.alias`. For `color/action/primary/bg`: light → `color/blue/600`, dark → `color/blue/400`, hc-light → `color/blue/800`, hc-dark → `color/blue/300`, linen → `color/ultramarine/600`, linen-dark → `color/ultramarine/300`. Never type a hex into the Semantic collection.

Number and string variables mostly have no mode differences (`space/inset/*`, `space/400`, `radius/md`, `radius/300`, `border/width/*`, `size/target/*`, `motion/duration/*`). The exceptions are the three type roles linen overrides — `font/body/*`, `font/label/*`, `font/heading/*` — which do differ per mode; check `modes` before assuming one value.

**Do not create variables for the CSS alias layer.** `--iz-color-bg-accent`, `--iz-space-400`'s colour equivalents and the `color/fg/on-*` pairs exist in CSS as aliases of canonical tokens (ADR-009); `dist/figma/tokens.json` deliberately omits them. In Figma there is exactly **one** variable per canonical token — a second variable pointing at it would be a duplicate to keep in sync by hand.

Text styles (Foundations page). The base theme is Inter; linen uses Space Grotesk (UI), IBM Plex Mono (labels) and Archivo wdth 112 / wght 700 (display and figures). Figma text styles cannot switch per mode, so make two sets and name them:
`Base/Body` (Inter 16/24 Regular), `Base/Label` (Inter 14/17 Medium), `Base/Control` (Inter 16 Medium), `Base/Heading` (Inter 30/36 Semibold);
`Linen/Display` (Archivo 56/56, −2 %), `Linen/Figure lg` (Archivo 40/40 tnum), `Linen/Figure` (Archivo 22/24 tnum), `Linen/Heading` (Space Grotesk 18/24 Semibold), `Linen/Title` (Space Grotesk 15/20 Semibold), `Linen/Body` (Space Grotesk 15/22 Regular), `Linen/Meta` (Space Grotesk 13/18), `Linen/Label` (IBM Plex Mono 11/16, +8 %, caps), `Linen/Code` (IBM Plex Mono 12/16).
Bind sizes to `font/size/*` variables where Figma allows; enable *tabular numbers* on every Archivo figure style.

## 3. Button component set (Components page)

Frame → Auto Layout, horizontal, *Hug* width, *Fixed* height bound to `size/target/md` (32). Padding left/right bound to `space/inset/md`, gap `space/inline/sm`. Corner radius `radius/md`. Stroke 1 bound to `border/width/sm`, colour `color/action/secondary/border`. Fill `color/action/secondary/bg`. Text layer "Label", style `Control`, colour `color/text/primary`.

Make it a component, then add **component properties** (right panel → +):

| Property | Kind | Values | Maps to (code) |
|---|---|---|---|
| `Variant` | Variant | `primary`, `secondary`, `tertiary`, `danger` | `variant` |
| `Size` | Variant | `sm`, `md`, `lg` | `size` |
| `State` | Variant | `default`, `hover`, `focus`, `active`, `disabled`, `pending` | browser states + `isDisabled` / `isPending` |
| `Label` | Text | "Save changes" | `children` |
| `Icon start` | Boolean + Instance swap | off | `iconStart` |
| `Icon end` | Boolean + Instance swap | off | `iconEnd` |
| `Full width` | Boolean | off | `isFullWidth` |

That is 4 × 3 × 6 = 72 variants — acceptable for the system's core control; do not add more axes.

Per variant, bind fills/strokes/text to the semantic variables exactly as `Button.module.css` does:
- `primary`: fill `color/action/primary/bg`, text `color/text/on-action`, stroke = fill. hover → `bg-hover`, active → `bg-active`.
- `secondary`: fill `color/action/secondary/bg`, stroke `color/action/secondary/border`, text `color/text/primary`; hover → `bg-hover`, active → `bg-active`.
- `tertiary`: no fill, no stroke, text `color/action/primary/fg`; hover → fill `color/action/secondary/bg-hover`.
- `danger`: as primary with `color/action/danger/*`.
- `disabled`: fill `color/action/disabled/bg`, text `color/action/disabled/fg`, stroke = fill.
- `focus` (every variant): add an outer stroke 2 (`border/width/focus`) in `color/border/focus`, positioned *outside*, with a 2 px gap — in Figma, use a second rectangle/stroke layer named "Focus ring" 4 px larger than the button on each side. The ring must be on every variant; it is the single most-forgotten state.
- `pending`: label at 0 % opacity (not hidden — mirrors `opacity: 0` in code), a 16 px "Spinner" instance centred.
- Sizes: `sm` height `size/target/min` (24), padding `space/inset/sm`, text style `Label`; `lg` height `size/target/touch` (44), padding `space/inset/lg`.

Set *Component description* to (copy verbatim):

```
Pattern: WAI-ARIA APG Button. Role: button.
Keyboard: Tab/Shift+Tab focus · Enter activates (key down) · Space activates (key up).
Focus ring: 2px outline color/border/focus, offset 2px, on every variant.
Targets: sm 24px (AA minimum) · md 32 · lg 44 (touch).
Props: variant, size, isDisabled, isPending, isFullWidth, iconStart, iconEnd; icon-only requires aria-label.
Never use for navigation (Link). Never disable submit to signal invalid form.
Spec: src/components/Actions/Button/Button.spec.json
```

## 4. Check the mirror

Switch the Semantic collection mode on a frame containing all four Button variants, through all six: `light` → `dark` → `hc-light` → `hc-dark` → `linen` → `linen-dark`. Every fill/stroke/text must change without touching the component. If anything stays the same, that property is bound to a primitive or a raw value — fix the binding.

`linen` is the sharpest test of the mirror, because it does not just tint the base theme — it **swaps the roles**: the page becomes warm (`color/surface/default` → `color/linen/100`, `#F7F5F0`) while cards become white (`color/surface/raised` → `color/white`). In the base theme it is the other way round. A Button bound to `color/surface/raised` must therefore go *white on a warm page* in linen. If it goes warm on white, the binding is inverted.

Then compare against code: `dist/css/linen.css` holds the same values as plain custom properties, so any mismatch is a binding error, not a token error.

Right-click the `Semantic` collection → *Export to JSON* (if available on your plan/version). Save as `tokens/figma-export/semantic.json` and run `npm run tokens:sync` (Phase 2) to diff against the source. Until then, the manual check in step 4 is the verification.
