# Tokens

Format: **DTCG 2025.10** (`$value`, `$type`, `$description`, `$extensions`, `$deprecated`, aliases as `{path.to.token}`).
Source of truth: `tokens/*.json`. Everything else is generated by `scripts/tokens-build.mjs` (ADR-006).
CSS prefix: `--iz-`. In CSS, always `var(--iz-*)`, never a raw value — enforced by `iz/no-raw-colors`, `iz/no-raw-spacing` (TS/TSX) and stylelint (CSS).

## Three tiers

| Tier | File | Who reads it | Example |
|---|---|---|---|
| Primitive | `tokens/primitives/*.json` | semantic tokens only | `{color.blue.600}` = `#2563EB` |
| Semantic | `tokens/semantic/*.json` + `tokens/themes/<theme>.json` | components | `{color.action.primary.bg}` → `{color.blue.600}` |
| Component | inside each `*.module.css` as scoped custom properties | that component | `--iz-button-padding-x: var(--iz-space-inset-md)` |

Rules: a component never references a primitive. A semantic token never holds a raw value — it aliases a primitive. Themes override *semantic* tokens only. If you need a new primitive for one component, you probably need a new semantic token instead.

## Naming

Path = `category.concept.property.variant.state`, lowercase, kebab inside segments, dots between.

```
color.text.primary
color.text.on-action
color.action.primary.bg
color.action.primary.bg.hover
color.border.focus
color.surface.raised
space.inset.md            # padding inside a thing
space.stack.md            # vertical gap between things
space.inline.md           # horizontal gap between things
size.target.min           # 24px (WCAG 2.5.8)  / size.target.touch = 44px
radius.sm | md | lg | full
border.width.sm | md | focus
shadow.raised | overlay
font.family.sans | mono
font.size.100 … 900       # t-shirt or numeric scale, never "h1"
font.weight.regular | medium | semibold
line-height.tight | normal | loose
duration.fast | normal | slow
easing.standard | emphasized
z.overlay | z.toast
```

CSS output flattens with the prefix: `{color.action.primary.bg}` → `--iz-color-action-primary-bg`.

Naming rules: name the *purpose*, not the value (`color.text.muted`, never `color.gray-500` outside primitives). Hover/active/disabled are the **last** segment. Never encode the component in a semantic token name — that's what the component tier is for.

**On-pairs.** Every background role has a foreground partner: `color.fg.on-<role>` in `tokens/semantic/color.pairs.json`, aliasing the canonical foreground so a theme overrides one place. `check:contrast` fails if a background role has no partner.

**Alias layer.** `specs/HANDOFF.md` uses a second scheme (`--iz-color-bg-accent`, `--iz-space-400`). Those names exist as aliases in `tokens/semantic/*.handoff.json`; the names above stay canonical. `--iz-color-bg-accent` and `--iz-color-action-primary-bg` are both real and always equal. Only `*.pairs.json` / `*.handoff.json` may alias semantic → semantic, and a theme may never override an alias-layer token. Full mapping and the three names that cannot be emitted verbatim: ADR-009.

## Types we use

`color`, `dimension`, `fontFamily`, `fontWeight`, `number` (line-height, opacity, z-index), `duration`, `cubicBezier`, `shadow`, `border`, `typography` (composite, for text styles only). Dimension values are objects: `{"value": 16, "unit": "px"}` — unit is required even for 0. Spacing/size in `px`; font sizes in `rem`.

## Themes

Registered in **`tokens/themes.config.ts`** — one entry per theme is the only step needed for validate, build and contrast to pick it up (ADR-011). Selected by `data-theme` **or** `data-iz-theme` on `<html>`; the generated CSS carries both selectors.

| Theme | Attribute | Extends | Contrast |
|---|---|---|---|
| Light | (default, `:root`) | — | AA 4.5:1 text, 3:1 UI |
| Dark | `dark` | — | AA |
| High-contrast light | `hc-light` | — | AAA 7:1 text, 3:1 UI |
| High-contrast dark | `hc-dark` | — | AAA |
| Linen | `linen` | — | AA |
| Linen dark | `linen-dark` | `linen` | AA |

Linen is the Job Search HQ theme (`specs/HANDOFF.md` § *Linen theme tokens*): warm paper, ultramarine accent, oxblood reserved for the `iz/design` mark. It overrides colour **and** the three type roles that collide with the base Inter scale; `linen.dark` extends it and overrides colour only. WCAG 1.4.11 has no AAA non-text level, so UI stays 3:1 even on the `hc-*` themes.

`prefers-color-scheme: dark` and `prefers-contrast: more` are bridged with media queries when no `data-theme` is set. Each theme is one file in `tokens/themes/` that re-aliases semantic tokens. The DTCG Resolver module (sets + modifiers) is the target structure once it's stable; until then Style Dictionary `include` (base) + `source` (theme) does the same job.

Reduced motion: `prefers-reduced-motion: reduce` sets all `duration.*` to `0ms` via a media query in the generated CSS.

## Contrast requirements baked into semantic pairs

Every `color.text.*` is defined *against* a `color.surface.*`, and `scripts/check-contrast.ts` verifies every documented pair in every theme — 288 graded pairs across 6 themes, run both as `npm run check:contrast` and as `src/test/contrast.test.ts` inside `npm test`. Input is `tokens/contrast-pairs.json`: `pairs` for combinations no convention implies, `onPairs` for the background/foreground partners. A background role with no `onPairs` entry fails the run (ADR-012). Pairs and thresholds:

- text on surface: 4.5:1 (AA), 7:1 in hc themes
- large text (≥ 24px or ≥ 19px bold) on surface: 3:1
- UI component boundaries (`color.border.*` on surface, icon on surface): 3:1
- focus ring (`color.border.focus`) against the surfaces it can appear on: 3:1. **Not** against the component it outlines: the ring is drawn with a 2 px offset, so a band of surface always separates the two (ADR-012).
- disabled states are exempt from contrast (WCAG) but must still be distinguishable; we keep ≥ 3:1 anyway where possible.

## Fonts

**The library names typefaces; it does not ship or load them.** `font.family.*` are `fontFamily` tokens with a real fallback stack, and nothing in `src/` declares `@font-face` (ADR-017). A consuming app loads the faces it needs — it owns subsetting, self-hosting vs CDN, `font-display` and its own CSP.

What a consumer must load for each theme:

| Theme | Role | Face | Weights / axes |
|---|---|---|---|
| base (`light`, `dark`, `hc-*`) | body, label, control, heading | Inter | 400, 500, 600 |
| `linen`, `linen-dark` | body, title, heading, meta | Space Grotesk | 400, 500, 600 |
| `linen`, `linen-dark` | label, code | IBM Plex Mono | 400, 500 |
| `linen`, `linen-dark` | display, figure, figure-lg | Archivo | 400, 700 at **wdth 112** |

Two things a variable font needs that a token cannot express: `font-variation-settings: 'wdth' 112` wherever Archivo is used (a variable font renders at its default width otherwise), and `font-variant-numeric: tabular-nums` on the figure roles so counts do not jitter as they change. The component that first uses the display role sets both.

Storybook loads all four faces from Google Fonts via `.storybook/preview-head.html`, so a design review shows the real typography. That file is Storybook-only and is not part of the library.

## Figma mirror

Figma Variables mirror the tiers one-to-one:

- Collection `Primitives` — no modes. Only colours, numbers, strings here.
- Collection `Semantic` — modes `Light | Dark | HC Light | HC Dark`. Every variable is an **alias** to a Primitive. No raw values.
- Collection `Component` — optional, only when a component needs a scoped override.
- Variable names use `/` as the group separator: `color/action/primary/bg`.

Export: right-click collection → *Export to JSON* (DTCG-shaped) → commit to `tokens/figma-export/` → `npm run tokens:sync` diffs against the source. Keep this manual path even if a plugin (Tokens Studio, Atomize) is added later, so we're never locked in. Preserve aliases on export — a flattened export is useless for theming.

Text styles, effect styles and grid styles reference variables where Figma allows it.

## Build

```
npm run build:tokens   # validate, then build
npm run tokens:validate
npm run tokens:build
npm run check:contrast # every documented pair, every theme
```

`tokens:build` writes:

| Output | For |
|---|---|
| `src/styles/design-tokens.css` | the package: `:root` base, one block per theme, OS bridges, reduced motion |
| `src/styles/tokens.d.ts`, `dist/ts/tokens.d.ts` | `TokenName` and `ThemeId` unions for editors and `check:specs` |
| `dist/css/<theme>.css` | one standalone file per theme, usable alone or via the attribute |
| `dist/figma/tokens.json` | Figma Variables mirror: `Primitives` (159, no modes) + `Semantic` (118, one mode per theme, aliases preserved). Collections and modes live in `$extensions["design.iz.figma"]`; the CSS alias layer is excluded on purpose (ADR-015) |
| `docs/specs/tokens.dtcg.json` | resolved values per theme, for MCP `list_tokens` and Claude Design |

Each theme block contains exactly the tokens that theme's extends-chain overrides — colour for most themes, colour plus type for linen. Alias-layer tokens are the exception: they are declared once on `:root` as `var(--iz-<canonical>)` so they follow their target into every theme (ADR-014).

Generated files are committed (so consumers and the MCP server don't need a build step) but never hand-edited; CI fails if the generated output differs from a fresh build.

`npm run tokens:validate` checks, before any build: every alias resolves; no alias cycles; every semantic token has a value in every theme; no duplicate names across files; every `$type` is one of the supported types and its `$value` has the matching shape (dimension `{value, unit}`, colour `{colorSpace, components, hex}`); no raw values in the semantic tier.

## Git ↔ Figma: what moves, and what is lossy

| Property | Git → Figma | Figma → Git (export) | Notes |
|---|---|---|---|
| colour (hex, alpha) | yes | yes | Figma exports sRGB; wide-gamut colour spaces are lossy |
| number (spacing, radius, line-height) | yes | yes | Figma numbers are unitless: `px` assumed; font sizes converted to `rem` in the build |
| string (font family) | yes | yes | — |
| alias | yes | yes, if the exporter preserves references | a flattened export is rejected by `tokens:sync` |
| `$description` | → variable description | partial | — |
| shadow, typography composites | manual (effect/text styles) | not exported as variables | documented manual step |
| `$deprecated`, `$extensions` | no | no | Git-only |
| modes ↔ themes | one mode per theme on the Semantic collection | export per mode | verify the export shape at Phase 1 before relying on it |

Unit rule: spacing/size/radius are `px` in Git and Figma; font sizes are `rem` in CSS (16px base) and `px` in Figma; the build converts and the manifest documents it.
