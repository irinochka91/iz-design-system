# TextField

Single-line text entry with a **visible label**, optional description and an error message that screen readers announce the moment it appears. Not for multi-line text (`TextArea`), choosing from options (`Select`, `ComboBox`) or dates (`DateField`).

Pattern: native `<input>` + `<label>` per the [WAI Forms tutorial](https://www.w3.org/WAI/tutorials/forms/) · Behaviour: React Aria `TextField` · Spec: `TextField.spec.json`

## Anatomy

`label` · field box (`[iconStart] input [kbdHint]`) · `description` · `errorMessage`. The **box** is the target and carries the border, background and focus ring — not the bare input. The error element is always in the DOM (empty while valid) so `aria-describedby` points at something stable and the text is announced as soon as `isInvalid` flips.

## Label and name

A visible label is the default and the accessible name. A field may drop it only by passing `aria-label` — the quick-add row does — and TypeScript refuses a field with neither. `placeholder` is an example value in muted text: never the label, never the instructions.

## Sizes

`md` 40 px (desktop control height, shared with Button — ADR-021) · `lg` 44 px (touch). No `sm`: a 32 px text field is rarely right for text entry.

## Keyboard

| Key | Action |
|---|---|
| `Tab` / `Shift+Tab` | Moves focus to / from the input; label, description, error and kbd hint are never tab stops |
| Typing | Edits the value; `onChange` fires with the string |
| `Enter` | **Not handled.** Submits a surrounding `<form>` natively; the quick-add pattern may listen |
| `Escape` | **Not handled.** The quick-add pattern clears, a Dialog closes — the field never stops propagation |

Global shortcuts (J/K/D/S/N/F) are suppressed inside editable elements by the app's handler, not by the field.

## States

Hover and focus are browser states via React Aria `data-*`. Semantic states are props: `isInvalid` (+ `errorMessage`), `isRequired`, `isReadOnly`, `isDisabled`. Invalid is never colour-only: thicker danger border **and** error text **and** `aria-invalid`.

## Do / Don't

- Do set `autoComplete` on personal-data fields (`email`, `given-name`, `organization`) — WCAG 1.3.5 and the biggest mobile win.
- Do set `type` / `inputMode` so phones show the right keyboard.
- Don't put instructions in `placeholder`; use `description`.
- Don't use native `required` on top of `isRequired` — the browser bubble would compete with the error message.
